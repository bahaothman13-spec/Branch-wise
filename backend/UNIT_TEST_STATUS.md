# حالة اختبارات الوحدة — BranchWise Backend

## الحالة والنطاق

تغطي مجموعة pytest الحالية قواعد الأعمال والأمان القابلة للاختبار بمعزل عن قاعدة البيانات. يقتصر هذا التقرير على اختبارات الوحدة واختبارات Flask المحلية؛ لا يثبت اتصالًا حقيقيًا بـ MySQL أو تكاملًا بين API وقاعدة البيانات. اختبار API التكاملي بقاعدة MySQL معزولة جزء من BE-54.

## التغطية الموجودة

| المجال | التغطية الحالية |
| --- | --- |
| المصادقة والجلسات | تجزئة كلمات المرور والتحقق منها؛ عشوائية رموز الجلسة وعدم تخزينها خامًا؛ تحميل الهوية والصلاحيات الحالية من مصدر موثوق؛ انتهاء الجلسة وإلغاؤها؛ خصائص cookies والتحقق من CSRF وحماية المسارات؛ إعدادات الإنتاج وفشل الاعتماديات المغلقة؛ حدود كلمات المرور؛ تكامل مسارات التسجيل والدخول والخروج ومحدد المحاولات وأخطاء المستودع عبر Flask test client ومستودعات وهمية للاختبار. |
| RBAC والعزل | مصفوفة الأدوار والمنح الموثوقة؛ رفض الصلاحية خارج الدور؛ عزل النشاط التجاري والفرع؛ قواعد الموارد ذات الصلة ونطاق التحويلات؛ واختبار عميل Flask لتركيب صلاحيات الجلسة مع نطاقات موارد محقونة للاختبار. لا يعني ذلك تفعيل حماية مسارات الأعمال الفعلية. |
| المنتجات والمتغيرات | الحقول والمعرّفات والأسعار العشرية الدقيقة والفئة النشطة؛ تفرد الأكواد داخل النشاط؛ تبعيات المنتج والمتغير؛ الصلاحيات والطلبات المقترحة وتغييرات الحالة. |
| المخزون وحركاته | الكمية المتاحة وحد إعادة الطلب؛ التحقق من الكميات؛ خطط البيع والشراء والتعديل والإلغاء والإرجاع والتحويل؛ تراكم التأثيرات ورفض الأرصدة السالبة والتأثيرات المكررة. |
| POS والمبيعات والإلغاء | أسعار الخادم ومجاميع السلة والسعر الدقيق؛ تجميع الأسطر المكررة والتحقق من توافر المخزون؛ صلاحيات النطاق؛ طلب الإلغاء والموافقة والرفض ومنع الاستعادة المكررة. |
| الإرجاع والفحص | أهلية الإرجاع والحد التراكمي مقابل البيع؛ التحقق من الإرجاع غير المرتبط؛ الفحص الجزئي وتصنيف التالف والقابل للبيع؛ سجل الفحوصات ومنع تجاوز الكميات أو إعادة معالجة الفحص. |
| سلامة المعاملات وidempotency | نطاق مفتاح الطلب، تطبيع/hash الحمولة، إعادة النتيجة المحفوظة، الطلب الجاري، تعارض الحمولة، وترتيب أقفال أرصدة المخزون. أضيف اختبار رفض التعارض أثناء الطلب الجاري ورفض سجل idempotency المحفوظ المشوّه. |

اختبارات API الموجودة تستخدم Flask test client للتحقق من التحقق من المدخلات والأمان والاستجابات الحالية. اختبارات قاعدة البيانات تستبدل موصل MySQL بـ mocks ولا تنفذ اتصالًا أو استعلامًا.

اجتازت المجموعة الكاملة في 7 نوفمبر 2026 عدد **1040 اختبارًا**. اختبارات التكامل الجديدة تستخدم مخازن ومستودعات وهمية داخل الاختبار فقط ولا تنشئ اتصالًا أو استمرارية وهمية في التطبيق الإنتاجي. اختبارات الأمان تتحقق أيضًا من رفض قاعدة SQLite الذاكرية في الإنتاج، ومن اشتراط مخازن جلسات مشتركة ومحدد محاولات مشترك وذرّي.

## الفجوات المعروفة

- لا يوجد تنفيذ تخزين معاملات/أرصدة دائم في هذه المجموعة يمكنه إثبات ذرية الكتابة أو rollback أو سلوك التزامن الحقيقي. قواعد الحركة وidempotency تختبر قرارات وخططًا خالصة فقط.
- مسارات الأعمال التي تعتمد على MySQL لم تُختبر من أول API إلى قاعدة البيانات ببيانات معزولة. يلزم لذلك مخطط قاعدة البيانات وإعداد تكامل معتمد في BE-54.
- لا تُعد نتائج هذه المجموعة اختبارات تكامل لقاعدة البيانات، ولا ينبغي وسم BE-54 كمكتمل بناءً عليها.

## التشغيل

من مجلد `backend`:

```bash
python -m pip install -r requirements.txt
python -m pytest -q
```

على Windows في بيئات ظهر فيها تعذر تنظيف مجلد pytest المؤقت العام، شغّل المجموعة بمجلد مؤقت محلي:

```powershell
python -m pytest -q --basetemp=.pytest-be53-basetemp
```

## الاعتماديات والخدمات

تُستخدم الاعتماديات المثبتة في `requirements.txt`، ومنها Flask وpytest وموصل MySQL وpython-dotenv. لم تُضف اعتماديات جديدة. اختبارات الوحدة لا تحتاج بيانات اعتماد أو خدمة MySQL أو API خارجية؛ يتم mock لاستدعاء موصل MySQL حيث يلزم.

## CI

يعمل سير GitHub Actions على Ubuntu عند تغييرات backend أو عقد API ذات الصلة في push وpull request. يثبت `backend/requirements.txt` ثم يشغّل `python -m pytest -q` من مجلد `backend`. لا يعرّف السير متغيرات أسرار أو بيانات اعتماد MySQL ولا يبدأ خدمة قاعدة بيانات.
